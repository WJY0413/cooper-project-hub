# 公司挖掘｜使用说明与独立包

公开同步快照：2026-10-15。保留原文工作方法；附件与企业依赖的调整见文末。

[返回项目目录](../README.md)

适用于已经明确产品和区域、但还缺少目标公司名单的 BD 工作。先确定哪些来源能产出名单，再确认公司官网与合作角色，把真正值得继续看的对象交给评级或联系人研究。

## 使用前准备

准备产品/合作目标、国家或区域、目标公司类型、排除条件、数量或时间预算，以及已经研究过的域名清单。没有历史名单时可以新建空的本轮索引，但只能说明“本轮未出现”，不能宣称公司在所有历史业务库中都是新增。

## 操作流程

1. 需要找方向时，先读 bd-source-direction-finder-share：比较品牌经销网络、展会、协会、服务商与采购中标名单，选择能实际列出公司的入口。
2. 用 general-list-mining-v2-1-share 分批搜索。目录和搜索摘要用于发现候选，正式入选理由要落到公司实际官网页面。
3. 研究前用包内 run-domain-dedupe-share 批量检查域名；保留结果与回执。命中域名不等于同一分支或实体，未命中也不等于通过业务资格判断。
4. 记录执行过的关键词、来源、候选与新增结果；连续三个成功搜索波次没有新增时换方向。访问失败单列，不能当作市场已经挖完。
5. 交付有官网和证据的名单、待核实对象及覆盖缺口。仅在任务明确要求时添加评级；公司评级规则已随包提供。

## 得到什么结果

每家公司至少保留名称、类型、区域、官网域名、来源链接、支持摘录、入选理由、去重结果与待核实事项。公司名单、关键词记录和证据按指定目录保存；不自动写入业务库或开始联系。

## 可以直接复制的请求

```text
请读取 skills/general-list-mining-v2-1-share/SKILL.md。目标：在【国家/区域】寻找【产品】的【经销商/服务伙伴】。排除【条件】，最多研究【数量/时间预算】。历史域名索引为【路径】，输出到【目录】。每家公司给官网与入选依据，暂不找个人联系人。
```

## 如何使用这个包

解压后先读本文件，再把本次任务和文章中的调用示例交给 AI。无需先改全局配置：可以让 AI 直接读取解压目录内 `skills/<名称>/SKILL.md`。若工具需要注册 Skill，再按该工具的导入方式添加包内各 Skill 文件夹；不要覆盖已有同名版本。脚本示例默认从本包根目录运行，`<...>` 或【...】均需替换为本人的实际输入。浏览器、网页搜索和 Python/ASR 是运行环境能力，不随 ZIP 安装。

需要具有网页搜索和打开能力的 AI 环境；该流程沿用内置 Web 路线。域名工具需要 Python 3。若启用结构化评级接收器，还需要 Python 3.10+ 与 jsonschema。本包包含来源规划、挖掘、去重和评级规则，不需要另外安装其他业务包。

本包包含以下 Skill：

- bd-source-direction-finder-share
- company-list-rating-v2-1-share
- general-list-mining-v2-1-share
- run-domain-dedupe-share

## 使用时容易混淆的地方

不要用裸域名数量代表合格客户数量。不要为了凑数量降低证据要求，也不要把网页打不开评成无价值。包内不含 Jarvis、多线程调度、历史业务数据库或真实客户名单。
