# 公司评级｜使用说明与独立包

公开同步快照：2026-10-15。保留原文工作方法；附件与企业依赖的调整见文末。

[返回项目目录](../README.md)

适用于已有公司名单，需要判断哪些公司应优先开发。评级依据是与本次产品和合作目标的适配度、实际合作能力和排除证据，不是网站精美程度或联系人邮箱数量。

## 使用前准备

提供公司名称、官网、区域、名单来源，以及本次目标定义和明确排除项。说明是否保留终端客户、承包商或只要经销商。批量结构化操作还需要任务 run_id、稳定 company_id 与独立的新台账。

## 操作流程

1. 先读 SKILL.md 与 references/rating-rules.md，固定本次产品、区域和目标公司类型，再开始评级。
2. 核实公司身份，读取能证明实际业务与合作能力的官网页面；同一页可以支持多条不同事实，不必为满足数量重复找链接。
3. 按 A+、A、A-、B+、B、C 或 pending_research 区分。C 必须有命中排除项的直接证据；信息不足进入待研究。
4. 非 C 公司保留有用的公司公共邮箱、总机、联系页或表单；将招聘、媒体、法务等限定用途入口与可用于商务联系的入口分开。
5. 结构化批量任务按 controller.md 创建独立 SQLite 台账，逐家公司提交并回读。接收器验证数据格式，研究者仍需核实证据是否支持结论。

## 得到什么结果

交付公司身份、简介、角色、评级、理由、证据与公司级公共联系入口，并单列未知项。台账回读可证明记录已保存，不能替代业务证据审核，也不等于已经进入生产 CRM。

## 可以直接复制的请求

```text
请读取 skills/company-list-rating-v2-1-share/SKILL.md 和 references/controller.md。对【名单路径】做评级，目标是【合作目标】，排除【规则】。创建新的独立本地台账，保留来源行号；逐家公司核实官网后提交并回读，不写入既有业务库。
```

## 如何使用这个包

解压后先读本文件，再把本次任务和文章中的调用示例交给 AI。无需先改全局配置：可以让 AI 直接读取解压目录内 `skills/<名称>/SKILL.md`。若工具需要注册 Skill，再按该工具的导入方式添加包内各 Skill 文件夹；不要覆盖已有同名版本。脚本示例默认从本包根目录运行，`<...>` 或【...】均需替换为本人的实际输入。浏览器、网页搜索和 Python/ASR 是运行环境能力，不随 ZIP 安装。

网页搜索/阅读能力；结构化接收器需要 Python 3.10+ 和 jsonschema。脚本、schema、评级规则、controller 操作说明及离线测试均在本包。单次默认处理一家公司，批量由同一控制流程顺序推进，不自动启动多个代理。

## 使用时容易混淆的地方

公司小、页面少、没有邮箱都不是自动降级理由。评级不能代替联系人深挖；禁止把姓名邮箱混作公司公共邮箱。评分台账和生产入库是两件事。
