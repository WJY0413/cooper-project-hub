# 会议纪要｜使用说明与独立包

公开同步快照：2026-10-15。保留原文工作方法；附件与企业依赖的调整见文末。

[返回项目目录](../README.md)

适用于客户会议、渠道沟通和项目讨论后的信息整理。除了摘要，还保留完整的带时间戳转录，使后续查找需求、承诺、报价讨论或行动项时能回到原始语境。

## 使用前准备

提供获准处理的音视频文件、会议日期和主题、已知参会人、可用字幕或议程、输出位置。多份录音需要说明先后关系；不能仅凭文件名认定属于同一会议。

## 操作流程

1. 检查文件完整性、时长、声道、语言和本地已有转录能力。原始媒体保持不变；缺少模型或依赖时说明缺口，不擅自下载或调用收费服务。
2. 生成完整时间戳转录，保留对话轮次。听不清、重叠和不确定词明确标记，不能用“合理推测”填补发言。
3. 区分说话人与所属一方；只有音频或旁证支持时才使用真人姓名，否则使用 Speaker 1 等中性标签。
4. 提炼客户需求、异议、承诺、决策、行动项和未决问题，并让关键结论关联时间戳。责任人、期限未明确时留空。
5. 按 references/output-format.md 输出一份会议上下文 Markdown，包含原始素材索引、全文转录和质量说明；重大质量限制另附报告。

## 得到什么结果

默认一个 meeting-context.md，包含可检索摘要、双方观点、决策、行动项、未决问题与完整转录。只有需要时再生成 Word、Excel 或正式分享稿；本包不包含任何真实录音或客户会议材料。

## 可以直接复制的请求

```text
请读取 skills/meeting-audio-transcript-minutes-skill-share/SKILL.md。处理录音【路径】，日期【日期】，已知参会人【名单】，主题【主题】。输出中文会议上下文，转录保留原语言及完整时间戳；未知发言人不要猜，行动项给依据，保存到【目录】。
```

## 如何使用这个包

解压后先读本文件，再把本次任务和文章中的调用示例交给 AI。无需先改全局配置：可以让 AI 直接读取解压目录内 `skills/<名称>/SKILL.md`。若工具需要注册 Skill，再按该工具的导入方式添加包内各 Skill 文件夹；不要覆盖已有同名版本。脚本示例默认从本包根目录运行，`<...>` 或【...】均需替换为本人的实际输入。浏览器、网页搜索和 Python/ASR 是运行环境能力，不随 ZIP 安装。

需要可读取媒体的环境和已有的本地转录工具/模型。Skill 本身不包含 ASR 引擎、模型或媒体工具；只有字幕时应说明哪些内容未经过音频校验，不能声称完整音频已听审。

## 使用时容易混淆的地方

会议摘要不是逐字稿，语音转录也不保证人物识别正确。事实、推断和建议分别表达；不自动把会议信息写入知识库、CRM 或给客户发送纪要。
