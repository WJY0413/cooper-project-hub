# 开发信｜使用说明与独立包

公开同步快照：2026-10-15。保留原文工作方法；附件与企业依赖的调整见文末。

[返回项目目录](../README.md)

适用于第一封开发信、展会前邀约、会后建立联系或有真实历史往来的轻量跟进。目标是让对方愿意回复或继续交流，而不是在第一封信里讲完产品和公司历史。

## 使用前准备

提供目标网站、收件邮箱或联系人、本人姓名/职位/公司、产品或合作方向、已经允许对外使用的能力点，以及希望对方采取的下一步。附带 sender_context_template.md 可帮助整理发件人背景。

## 操作流程

1. 先检查发件人身份与目标公司信息，不能沿用包作者的姓名、职务或业务承诺。
2. 默认查看目标官网的相关业务；用户明确要求不联网时只依据所提供材料，不制造已研究过的口吻。
3. 选择一个合作角度。销售岗位偏向客户与渠道，技术岗位偏向应用与服务，管理岗位偏向业务适配；这些只是写作侧重点，不代表未经核实的个人偏好。
4. 写清本人身份、2–4 个有依据的能力点和一个轻量下一步。正文通常控制在 120–180 个英文单词，保持自然段间距。
5. 核对产品陈述、客户关系、附件和 CTA，交付 Subject 与 Email Body。草稿之外的实际发送另行操作。

## 得到什么结果

一份可以复制的英文主题与正文；需要时附简短内部切入点说明。默认不追加邮箱签名、不报价、不声称附上未提供的目录，也不生成多余版本。

## 可以直接复制的请求

```text
请读取 skills/b2b-website-outreach-email-share/SKILL.md。目标网站【URL】，联系人【已知姓名/团队】，我的身份【姓名、职务、公司】，产品【类别】，可公开优势【事实】，希望下一步【简短沟通/发送资料】。写一封约 140 词的英文开发信，仅草稿，不发送。
```

## 如何使用这个包

解压后先读本文件，再把本次任务和文章中的调用示例交给 AI。无需先改全局配置：可以让 AI 直接读取解压目录内 `skills/<名称>/SKILL.md`。若工具需要注册 Skill，再按该工具的导入方式添加包内各 Skill 文件夹；不要覆盖已有同名版本。脚本示例默认从本包根目录运行，`<...>` 或【...】均需替换为本人的实际输入。浏览器、网页搜索和 Python/ASR 是运行环境能力，不随 ZIP 安装。

默认需要官网阅读能力；用户提供充分背景并要求不联网时可直接写稿。无需 Python、邮箱账号或发送工具。

本包包含以下 Skill：

- b2b-website-outreach-email-share

## 使用时容易混淆的地方

不要把客户官网简介复述给客户，不要从邮箱前缀断言姓名，不编造采购权、既往交流、排名、认证或竞品缺陷。只有真实已发生的交流才能写成 follow-up。
