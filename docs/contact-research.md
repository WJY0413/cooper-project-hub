# 联系人研究｜使用说明与独立包

公开同步快照：2026-10-15。保留原文工作方法；附件与企业依赖的调整见文末。

[返回项目目录](../README.md)

适用于已经选定公司，想知道应该找谁、有哪些实际公开联系入口，以及哪些公司事实可支持后续开发。可以从一个公司名称或官网开始，不要求先配置调度器或数据库。

## 使用前准备

提供公司名称或官网、国家/地区线索、联系目的、已知人员或联系方式，以及希望的深度和输出目录。公司同名或身份有歧义时，应先消歧再把人员归到公司。

## 操作流程

1. 确认官方身份，读取官网的业务、联系、团队和介绍页面，形成有来源的简短公司背景。
2. 围绕联系目的寻找负责人：例如所有者、管理层、销售、渠道、产品或服务负责人；对有价值的线索继续查公司公告、品牌伙伴、行业活动与公开职业资料。
3. 区分个人邮箱/电话/LinkedIn、部门入口与公司通用入口。公开值逐字保留，不从邮箱格式猜地址，不把公司总邮箱写成某人的直达邮箱。
4. 收集可用于沟通的业务事实和历史项目，关联来源与日期。角色冲突、旧任职、限定用途地址等只在影响使用时明确标注。
5. 按 evidence-contract.md 保存实际获得的来源文字、链接、采集时间与相关摘录；区分完整文本、部分文本、搜索摘要和无法访问的内容。

## 得到什么结果

一份包含公司身份与简介、相关人员、公开联系路线、可引用业务事实、来源及局限的研究记录。找不到个人邮箱时，仍可交付有用的人员线索与公司入口，不能编造“已验证直达”。


## 如何使用这个包

解压后先读本文件，再把本次任务和文章中的调用示例交给 AI。无需先改全局配置：可以让 AI 直接读取解压目录内 `skills/<名称>/SKILL.md`。若工具需要注册 Skill，再按该工具的导入方式添加包内各 Skill 文件夹；不要覆盖已有同名版本。脚本示例默认从本包根目录运行，`<...>` 或【...】均需替换为本人的实际输入。浏览器、网页搜索和 Python/ASR 是运行环境能力，不随 ZIP 安装。

具有网页研究能力的 AI 工具，以及可写入证据的本地目录。没有文件能力时可以交付允许范围内的摘录与链接，并说明未保存原文。不依赖专用 MCP、接收器、Python 或其他业务包。

## 使用时容易混淆的地方

姓名并不证明当前任职，职务并不自动证明采购权；历史资料不能写成现状。仅研究公开商务信息，不绕过登录限制，不自动写开发信或发送消息。
